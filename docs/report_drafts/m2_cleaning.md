## For 2.1 Data quality: label origin

The dataset description does not say how the tweets were labelled. Because a lexicon-based labeller would make our models imitate that tool, we tested whether the labels can be reproduced by VADER, a widely used rule-based sentiment analyser, with its recommended ±0.05 threshold on the compound score.

VADER applied to the raw tweet text reproduces 93.0% of the labels (Cohen's κ = 0.89), while TextBlob, a different sentiment lexicon, reproduces only 59.9% (κ = 0.39). Agreement falls to 87.8% when VADER reads our cleaned text, which indicates that the labels were computed on the original text. Two further observations fit the same explanation: non-English tweets, which VADER cannot read and scores as neutral, are labelled *Neutral* 72% of the time (24% for English tweets, see Figure *cleaning_label_by_language*), and tweets whose emoji were lost in the file agree slightly less often (91.0% vs 93.7%).

We therefore treat the labels as **probably generated by VADER**. This is a hypothesis we cannot prove without the original pipeline, but it has three consequences for the project: the classification task effectively means learning to imitate a sentiment lexicon; VADER scores are never used as a model feature, since that would leak the label; and the 116 tweets where VADER and the given label disagree are kept as candidates for label-noise analysis.

The steps run in a fixed order because several depend on each other: mentions are replaced before underscores are interpreted, unreadable tweets are detected before placeholders hide the mojibake, and language is detected before the `#` symbols are removed (otherwise hashtag words such as *stockmarketcrash* confuse the detector). *Conflicting labels.* No exact or content duplicate had conflicting labels, so no row was removed for that reason. One near-duplicate pair (the same tweet addressed to two different users) is labelled *Positive* in one copy and *Negative* in the other; both are kept, grouped, and listed among the label-noise candidates.

*What was not removed.* No tweet was removed for its length or as an outlier: a one-hashtag tweet and a 400-character thread are both legitimate tweets. There are no missing values in either column.

*Class balance.* Cleaning removed mostly *Neutral* rows (hashtag-only duplicates and unreadable tweets). The final distribution is Positive 625 (37.8%), Neutral 534 (32.3%) and Negative 495 (29.9%), a largest-to-smallest ratio of 1.26. This mild imbalance is handled with stratified splitting, macro-averaged metrics and class weights.

## 3.3 Text representation (normalisation part)

Two versions of each tweet are produced, because the models need different inputs:

- **`text_light`** keeps case, punctuation and the `[UNK]` placeholder. Transformer encoders such as Sentence-BERT use capitalisation and punctuation, so we only repair the text.
- **`text_full`** is fully normalised for the TF-IDF baseline and the self-trained FastText: contractions are expanded (*don't* → *do not*), text is lowercased, only letters are kept (punctuation and digits removed), words are lemmatised with WordNet using part-of-speech tags (*selling* → *sell*), and NLTK English stopwords are removed **except negations** (*no, not, never, nor …*), since removing them would turn "not bullish" into "bullish". A `text_full` tweet has 15 tokens on average (median 14, maximum 52).

The placeholder `[UNK]` survives as the token *unk*, so models can still see that a character such as an emoji was present even though its meaning was lost.
